# GoCode v0.7.4 — Security & Harness Release

**Released:** 2026-11-13

This release hardens the approval boundary and session storage, then closes the biggest harness gaps: real context compaction, model-aware budgets, parallel read-only tools, session-scoped approval grants, a plan tool with optional auto-verification, per-turn metrics, headless mode, and a deterministic eval suite.

## Security

- **Real approval diffs** — file previews now use a Myers/LCS unified diff, so a one-line insertion no longer renders as a whole-file rewrite. `/commit` shows the exact file list and commit message before asking for approval.
- **Terminal-safe rendering** — model/tool text, streamed deltas, tool output, and approval previews are sanitized (CSI/OSC/C0/C1) before reaching the terminal or TUI. Approval previews are delimited so injected text cannot spoof the prompt.
- **Preview-to-write integrity** — approved writes and patches record the resolved path and content hash; execution is refused with “file changed since approval — re-approval required” if the file or symlink target changed.
- **Secret containment** — shell and MCP children no longer inherit credential-shaped env vars (`*_API_KEY`, `*_TOKEN`, `*_SECRET`, `*_KEY`, configured provider `api_key_env`, plus `[tools.shell] env_scrub`). Tool-call arguments are redacted at the transcript/export boundary, not just tool results.
- **Owner-only storage** — session dirs are `0700`; `sessions.db`, `-wal`, and `-shm` are `0600` and re-checked on open. Config and log files are `0600`; `gocode doctor` flags group/other-readable session files.
- **Workspace-scoped resume** — sessions persist their workspace and auto-resume only in the same repository; the system prompt is rebuilt on resume. Explicit `--session <id>` still loads a chosen transcript.
- **Bounded execution** — file reads and code searches cap file size/line scans and stream ranges; provider error bodies are limited; shell timeouts kill the whole process group; hardlink identity checks are cached and invalidated on write; MCP advertises `readOnlyHint` and restarts dead servers once on demand.
- **Config validation** — provider `base_url` overrides are validated at load (HTTPS except loopback, no userinfo/query/fragment). Inline `api_key` values produce a startup/doctor warning.
- **Truncation is no longer an error** — OpenAI-shaped, Anthropic, and Ollama providers surface `finish_reason=length|max_tokens` as a normal terminal finish; the already-streamed partial answer is kept in history with a single notice.

## Harness

- **Real compaction** — `/compact` asks the active model to summarize goals, decisions, open files, and next steps; falls back to the placeholder summary when the provider cannot answer. System prompt, summary pair, and recent turns are preserved.
- **Model-aware budgets** — `max_context_tokens = 0` (new default) derives the budget from the model family’s context window (80%); an explicit value still wins.
- **Better token estimation** — CJK text and punctuation-heavy code are weighted above Latin prose.
- **Persistent scratchpad** — new `scratchpad` tool stores agent working state in the session and system prompt; it survives compaction and restarts (new `sessions.scratchpad` column, migrated in place).
- **Parallel read-only tools** — `file_read`, `code_search`, `plan`, and MCP tools advertising `readOnlyHint` run concurrently (bound 4) after sequential approvals; mutating tools stay serialized; results remain in call order.
- **Approval grants** — `[a]llow exact args this session`, `[r]ead-only tools this turn`, and `[e]dit` (plain mode) options; grants are in-memory, exact-args only, and die with the session.
- **Plan + auto-verify** — new `plan` tool; `[tools] verify_command` and `verify_timeout_seconds` run once per mutating round and feed failures back to the model.
- **Observability** — one structured `turn.metrics` slog line per turn (tokens, durations, tool counts/latency, approval counts, truncation/compaction, retries) with no content or paths.
- **Headless + evals** — `--headless` JSONL stdin/stdout protocol with `--policy` allow/deny JSON (unlisted tools are denied), and `make eval` runs a deterministic scripted-provider suite covering tool selection, truncation, approval gating, compaction, and resume.
- **MCP robustness** — configurable per-server `request_timeout_seconds`, tool count/name/description/schema caps, approval previews, scrubbed env, and on-demand restart after a dead server.

## Upgrade notes

- `max_context_tokens` now defaults to `0` = auto (per-model window). Set an explicit value to pin the old fixed budget.
- The interactive approval prompt accepts `y` (once), `a` (exact args this session), `r` (read-only tools this turn), `e` (edit, plain mode only), `n`.
- Sessions recorded before this release have no workspace binding and are therefore not auto-resumed; use `--session <id>` or `/resume <id>`.
- Cleartext non-loopback provider `base_url` overrides are rejected at config load.
- New config keys: `[tools.shell] env_scrub`, `[tools] verify_command`, `[tools] verify_timeout_seconds`, `[mcp.servers.<name>] request_timeout_seconds`.
- `redact_secrets` applies only to `shell_exec` output; transcript/export redaction is unconditional.

## Known limitations (documented in `docs/SECURITY.md`)

- `go-git/v5` remains for gitignore parity; its advisory surface is tracked by CI `govulncheck` rather than swapped.
- Hardlink identity checks probe a fixed list of external sensitive paths; aliases of other external files remain undetected (path confinement still applies).
- TUI approval supports y/a/r/n but not the plain-mode argument editor (`e`).
- Eval coverage is deterministic/scripted, not a live-model benchmark.

## Verification

`go build ./...`, `go vet ./...`, and `go test ./...` pass locally; `go test -race` passes on the core packages with cgo enabled. CI runs build/`vet`/tests on Ubuntu, macOS, and Windows, with the race detector on Ubuntu. Release binaries are built by GoReleaser and the npm archives are SHA-256 verified against `checksums.txt` before extraction.
